# AbeloHost

## Технологический стек:

PHP 8.4, Smarty, MySQL, Docker, SCSS

## Описание задачи

Сайт должен реализовать функционал блога с категориями и постами.

### Структура данных:

Категория: Название, Описание;

Статья: Изображение, Название, Описание, Текст, Категория (одна/несколько), Кол-во просмотров;

### Обязательные страницы:

- Главная страница:
  - Вывести каждую категорию, в которой есть статьи и отобразить 3 последних поста (по дате публикации).
  - Вывести кнопку “Все статьи” для каждой категории.
- Страница категории:
  - Вывести название, описание, список статей
  - Реализовать сортировку статей (по кол-во просмотров, по дате публикации)
  - Реализовать пагинацию
- Страница статьи:
  - Вывести всю информацию о статье
  - Вывести блок из 3 похожих статей

## Запуск проекта

```bash
docker compose up --build -d
```

## Описание процесса разработки и принятых решений (ADR)

В работе использовал: PhpStorm, Docker, Codex + Pi.

Использование ИИ инструментов считаю отличным решением для рутинных и точечных задач.

Хотя весь проект можно реализовать одним запросом, считаю недопустимо такое применение для коммерческого проекта.

---

### Этап "Подготовка":

Проект реализован через слоистую архитектуру с единой точкой входа public/index.php, реализованная по аналогии со структурой Laravel, 
т.к. такая структура знакома большинству разработчиков. Хотя на старте может выглядеть избыточной для маленького проекта.

Начальную структуру папок и файлов сформировал вручную.

Конфигурацию для докера сформировал ИИ по причине колоссального экономии времени.

---

### Этап "Проектирование БД":

Для проекта используются три таблицы categories, posts и post_categories для формирования связи "многие ко многим", т.к.
статьи могут относиться к нескольким категориям. Учтено мягкое удаление.

Ручная работа: написал базовый SQL-скрипт, определил название таблиц и колонок.

ИИ: валидация и правки дампа. Генерация для внешних ключей.

---

### Этап "Миграция и наполнение (сиды) БД":

Добавил класс подключения к БД на стандартный PDO, его возможностей достаточно для рабочего сайта.

ИИ: Всю работу по миграции и наполнению делал ИИ. Нейросеть отлично справилась за один запрос. Я лишь выбрал тематику статей и проверил результат.

---

### Этап "Класс приложения Kernel":

Добавил класс Kernel как центральный компонент приложения. Он является singleton и final, гарантирующий одну конфигурацию.

---

### Этап "DI":

Класс контейнер для зависимостей. Стандарт для слабой связанности, предсказуемости и удобства разработки и тестирования.
В контейнер добавил и сам Kernel, для доступа в любом экземпляре.

ИИ: подсказывал с классом-рефлексией

---

### Этап "Добавление роутера":

Добавление класса роутинга. Написание полноценного кастомного роутера с нуля — это трудоемкий процесс.
Для текущего проекта написал необходимый минимум, закрывающий требования ТЗ.

ИИ: точечно помог написать методы match (совпадение маршрутов) и invoke (вызов контроллеров).

---

### Этап "Frontend: верстка и стили":

Добавил исходники SCSS c модульным разделением на компоненты и страницы.
В рамках текущего проекта один собранный файл подключается на все страницы.
По мере роста проекта для тяжелых страниц стоит сделать отдельные бандлы.
Подключать один общий плюс для каждой тяжелой страницы свой.

ИИ: набросал базовый каркас верстки, после чего я прошелся и вручную внес правки.

**Считаю использование "&" для формирования классов в SCSS неоправданно дорогим в плане поддержки (усложняет глобальный поиск). Названия классов в стилях должны оставаться явными.**

---

### Этап "Backend: контроллер и запросы":

Сознательно отказался от написания "построителя запросов".
Использовал явные запросы под текущие задачи. Просто читаются, легко поддерживаются.

ИИ: помогла быстро составить SQL запросы для сложных выборок.

**Пагинацию по индексам не делал, на данный момент это избыточно. А так же есть сортировка по неуникальному полю views**

**DTO не использовал**

---

## Заметки (Технический долг и масштабирование):

- Текущий `docker-compose.yml` настроен исключительно для локальной разработки
- database.sql - исключительно для агентов.
- Необходимо логирование ошибок/событий.
- JavaScript не используются (хотя никто незапрещал), но нужно обязательно кэширование запросов и ленивая загрузка блоков.
- Следует добавить DTO
- Нормальный счетчик просмотров, например через redis и cron.
- Нужна валидация запросов
- Плохо хранить просто ссылку изображения в БД, нужна отдельная таблица для файлов с файловым хранилищем, нормализацией и так далее.
- Контроллер перегружен
- Нет тестов
